## The big findings (READ THIS)
1. **Cartographer is UNSTABLE on a feature-poor track.** On the open-U soft-hose track it lost tracking: `map` frame disappeared (`"map" does not exist`) and pose teleported (a logged lap came out at x≈25, y≈−9, garbage). EKF `odom→base_link` stayed rock-solid throughout.
2. **2D can't cleanly map a soft round 30cm hose.** We fixed every 2D knob (360°, slice, range 4.0, threshold) — occupancy stayed sparse/noisy. We flatten the 3D MID-360 cloud to a thin 2D `/scan` and discard height (`pointcloud_to_laserscan` → Cartographer `use_trajectory_builder_2d`). **3D hardware, 2D software.**
3. **Derek vs ours — corrected understanding.** Derek's `feat/manual-map-ekf-pursuit` made a *clean* map (`map_cart_20260603_035938_racetrack_map.png`). It is NOT just smoothing — the **data was genuinely cleaner**: his run had walls consistently on BOTH sides → `left/right_wall_m` std 0.24-0.34, ~few outliers. Our open-track runs: std 0.46, 192 left readings >1.5m + 259 right <0.3m (one side open → garbage). Derek's simple single-beam `left_wall_m/right_wall_m` method works great **when both walls are continuously present**. Our occupancy-ray-cast needs Cartographer to build solid walls (soft hose breaks that).
4. **The fix is the TRACK, not the algorithm.** New design (built today): a **closed loop "0 with an I inside"** — drive the ring between an **inner wall (box)** and **outer wall (hose + wall-with-window-hole)**. Left beam sees box, right sees hose/wall → both walls present → clean single-beam data AND enough structure for stable Cartographer. The **window hole is an open-wall gap** — handled by `range_max 4.0` + SLAM loop-closure bridging, NOT by slicing (slicing = height; a gap is a gap at any height).
5. **TA said "Cartographer + EKF will fix mapping."** Correct — it failed before only because the OLD track was feature-poor. The two-walled closed loop gives it the structure it needs. Try 2D first.
